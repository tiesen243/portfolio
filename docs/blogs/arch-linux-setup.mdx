## Introduction

Arch Linux is a great choice if you want a fast, minimal, and highly customizable desktop. In this guide, I’ll walk through my current Arch Linux setup with Hyprland/Niri, Noctalia, Neovim, Zsh, and a few other tools I use daily.

Everything is managed through my YukiOS dotfiles, so most of the setup can be automated with a single installer.

## Installation

### Requirements

- A usb drive with at least 8GB of storage
- A ISO image of Arch Linux [Download](https://archlinux.org/download/)
- A computer with a 64-bit processor
- A stable internet connection

### Installation steps

#### 1. Setup

**First**, you need to download the Arch Linux ISO image from the Arch Linux website. You can download the ISO image from the Arch Linux website by clicking on the download link on the Arch Linux website.

**Second**, use `Ventoy` to burn the ISO image to the USB drive. You can download Ventoy from this [website](https://www.ventoy.net/en/download.html). Once you have downloaded Ventoy, you can craete bootable USB, then copy the ISO file to this.

**Third**, plug the USB drive into the computer that you want to install Arch Linux on. Then, you need to boot the computer from the USB drive. You can do this by restarting the computer and pressing the boot menu key when the computer starts up. The boot menu key is usually F12, but it can vary depending on the computer. Once you have booted the computer from the USB drive, you need to select the Arch Linux installation option from the boot menu.

**Finally**, started to install Arch Linux on your computer. You can follow the Arch Linux installation guide to install Arch Linux on your computer.

```bash
# Increase the font size
setfont ter-120n
```

Check the internet connection.

```bash
ping google.com
```

If the internet connection is not working, you can use the following command to connect to the internet.


#### 2. Partition the disk with `btrfs` filesystem

```bash
# Show the available disk
lsblk

# Choose the drive has at least 50GB of storage
# Use cfdisk to create a new partition table on the drive
cfdisk /dev/[drive_name]
```

Create the partitions on the drive.

- Move the cursor to the free space and press `Enter`
- Select the `New` option and press `Enter`
- Set the size of the partition is `512M` and press `Enter`
- Select `type` to `EFI System` and press `Enter`
- (Optional) Go to the remaining free space, select New, set your desired Swap size (e.g., `4G` or `8G`), press Enter, then change its type to `Linux swap`.
- Go to the free space again and select the `New` option and press `Enter`
- Set the size of the partition is at least `40GB` and press `Enter`

  <Callout>

  This main partition will house your Btrfs subvolumes (including your root and home directories). You can scale the sizes according to your hardware. A complete system installation only takes around 6GB, leaving plenty of room for your files and applications.

  </Callout>

- Select `write` and press `Enter` to write the changes to the disk then `quit` to exit the cfdisk

```bash
# Format the partitions (Adjust the partition numbers based on your cfdisk layout)
mkfs.fat -F32 /dev/nvme0n1p1 # Replace with your EFI (512M) partition
mkswap /dev/nvme0n1p2        # (Optional) Replace with your Swap partition
mkfs.btrfs /dev/nvme0n1p3    # Replace with your Main Btrfs (>= 40G) partition

# Activate swap if you created one
swapon /dev/nvme0n1p2

# Mount the main partition to begin subvolume creation
mount --mkdir /dev/nvme0n1p3 /mnt

# Create the subvolumes for the system (Based on CachyOS subvolume layout)
btrfs subvolume create /mnt/@
btrfs subvolume create /mnt/@home
btrfs subvolume create /mnt/@root
btrfs subvolume create /mnt/@srv
btrfs subvolume create /mnt/@cache
btrfs subvolume create /mnt/@log
btrfs subvolume create /mnt/@tmp

# Unmount the root fs to remount with proper configurations
umount /mnt

# Mount the subvolumes to the system with zstd compression optimization
mount -o compress=zstd,subvol=@ /dev/nvme0n1p3 /mnt
mkdir -p /mnt/{home,root,srv,var/cache,var/log,var/tmp}
mount -o compress=zstd,subvol=@home /dev/nvme0n1p3 /mnt/home
mount -o compress=zstd,subvol=@root /dev/nvme0n1p3 /mnt/root
mount -o compress=zstd,subvol=@srv /dev/nvme0n1p3 /mnt/srv
mount -o compress=zstd,subvol=@cache /dev/nvme0n1p3 /mnt/var/cache
mount -o compress=zstd,subvol=@log /dev/nvme0n1p3 /mnt/var/log
mount -o compress=zstd,subvol=@tmp /dev/nvme0n1p3 /mnt/var/tmp

# Mount the EFI partition
mkdir -p /mnt/boot
mount /dev/nvme0n1p1 /mnt/boot
```

#### 3. Install packages

- `base`, `base-devel`, `linux`, and `linux-firmware` are the essential packages for the Arch Linux system.
- `intel-ucode` for Intel CPU microcode updates, which can improve system stability and security. (use `amd-ucode` if you have AMD CPU)
- `btrfs-assistant` and `btrfs-progs` are the tools for managing the Btrfs filesystem.
- `efibootmgr`, `grub`, `grub-btrfs`, and `os-prober` are the tools for managing the bootloader and dual booting with Windows
- `inotify-tools` is the tool for monitoring file system events, which is used by `snapper` to automatically create snapshots when there are changes in the file system.
- `snap-pac` and `snapper` are the tools for managing Btrfs snapshots, which can be used to create and manage snapshots of the file system.
- `pipewire`, `pipewire-alsa`, `pipewire-pulse`, and `pipewire-jack` are the tools for managing audio on the system, which is used for audio management
- `git` is the version control system, which is used for managing the configuration files and dotfiles.
- `neovim` is the text editor, which is used for editing the configuration files and writing code.
- `networkmanager` is the tool for managing network connections, which is used for managing the network connections on the system.
- `openssh` is the tool for managing SSH connections, which is used for managing SSH connections on the system.
- `reflector` is the tool for managing the mirror list, which is used for managing the mirror list on the system.
- `sudo` is the tool for managing the sudo permissions, which is used for managing the sudo permissions on the system.
- `wireplumber` is the tool for managing the audio routing, which is used for managing the audio routing on the system.

```bash
pacstrap -K /mnt base base-devel linux linux-firmware intel-ucode \
  btrfs-assistant btrfs-progs efibootmgr grub grub-btrfs inotify-tools os-prober snap-pac snapper \
  pipewire pipewire-alsa pipewire-pulse pipewire-jack \
  git neovim networkmanager openssh reflector sudo wireplumber
```

<Callout type="warning">

If you encounter a "Failed to install packages to new root" error when running, you may need to update the Arch Linux keyring before proceeding:

```bash
pacman -Sy archlinux-keyring
```

</Callout>

#### 4. Fstab and chroot

```bash
genfstab -U /mnt >> /mnt/etc/fstab

# verify the fstab file
cat /mnt/etc/fstab

# Chroot into the new system
arch-chroot /mnt
```

#### 5. Setup timezone, language and keyboard layout

Set the timezone for your system by creating a symbolic link from the appropriate timezone file in the `/usr/share/zoneinfo` directory to the `/etc/localtime` file.

```bash
# Replace Asia/Ho_Chi_Minh with your timezone
ln -sf /usr/share/zoneinfo/Asia/Ho_Chi_Minh /etc/localtime

# Now synchronize the hardware clock with the system clock by running the following command.
hwclock --systohc
```

Uncomment the locale you want to use in the `/etc/locale.gen` file and generate the locale by running the following command.

```bash
nvim /etc/locale.gen

locale-gen
```

Next, set the `LANG` variable in the `/etc/locale.conf` file to the locale you want to use. For example, if you want to use `en_US.UTF-8` locale, you need to set the `LANG` variable as follows.

```bash title="/etc/locale.conf"
LANG=en_US.UTF-8
```

Finally, set the keyboard layout for the system. For example, if you want to use `us` keyboard layout, you can run the following command.

```bash title="/etc/vconsole.conf"
KEYMAP=us
```

#### 6. Hostname and Host configuration

Set the hostname for your system by creating a file named `/etc/hostname` and adding your desired hostname to it.

```bash title="/etc/hostname"
arch-btw
```

Next, you need to configure the hosts file to map the hostname to the loopback address. You can do this by editing the `/etc/hosts` file and adding the following lines.

```bash title="/etc/hosts"
127.0.0.1 localhost
::1 localhost
127.0.1.1 arch-btw
```

#### 7. Root password and user creation

Set the root password for your system by running the following command and following the prompts.

```bash
passwd
```

Next, create a new user for your system by running the following command and following the prompts. Replace `username` with your desired username.

```bash
useradd -m -G wheel username
passwd username
```

Finally, you need to edit the sudoers file to allow the new user to use `sudo` command. You can do this by running the following command and finding the line that is `## Uncomment to allow members of group wheel to execute any command` and uncommenting the line below it.

```bash
EDITOR=neovim visudo
```

```bash title="/etc/sudoers"
...
## Uncomment to allow members of group wheel to execute any command
%wheel ALL=(ALL:ALL) ALL
```

#### 8. Install and configure the bootloader (dual boot with Windows 11)

```bash
grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=arch
grub-mkconfig -o /boot/grub/grub.cfg
```

Then, config `grub` boot menu

```bash
nvim /etc/default/grub
```

Uncomment the following line

```bash title="/etc/default/grub"
GRUB_DISABLE_OS_PROBER=false
```

Generate the grub configuration file again to apply the changes

```bash
# Mount the EFI partitions of Windows 11
lsblk # Check the EFI partition
mount --mkdir /dev/[drive_name] /mnt/windows # Replace [drive_name] with the EFI partition of Windows 11

# Run os-prober to detect the Windows 11 installation and add it to the grub configuration
os-prober
grub-mkconfig -o /boot/grub/grub.cfg
```

#### 9. Umount everything and reboot

```bash
# Enable the NetworkManager service to start at boot
systemctl enable NetworkManager

# Exit the chroot environment
exit

# Unmount everything to check if the drive is busy
umount -R /mnt

# Reboot the system and unplug the installation media
reboot
```

### 10. Setup `snapper` for Btrfs snapshots

Initialize a snapshot configuration named `root` for the root (/) filesystem:

```bash
snapper -c root create-config /
```

Then, enable the `grub-btrfsd` service to automatically update the GRUB menu with available snapshots:

```bash
sudo systemctl enable grub-btrfsd
```

### Manual installation

If you prefer to inspect what goes onto your system, want to customize the setup, or need to troubleshoot a specific step, you can follow the step-by-step breakdown below.

#### 1. Install necessary packages

1.1. Install `yay`

```bash
pacman -Syu --needed git base-devel
git clone https://aur.archlinux.org/yay.git ~/yay
cd ~/yay
makepkg -si
rm -rf ~/yay
```

1.2. Clone `dotfiles` repository to get the list of packages to install

```bash
git clone https://github.com/tiesen243/dotfiles.git ~/dotfiles
```

1.3. Install packages

```bash
yay -S --needed --noconfirm --answerclean All --answerdiff None \
  $(grep -v '^#' ~/dotfiles/package.txt)

# Choose the compositor you want to use
yay -S --needed hyprland xdg-desktop-portal-hyprland
# or
yay -S --needed niri xdg-desktop-portal-gnome
# or install both
yay -S --needed hyprland niri \
  xdg-desktop-portal-hyprland xdg-desktop-portal-gnome
```

The automatic installer uses the same compositor choices and installs the matching desktop portal packages.

1.4. Set `zsh` as the default shell

```bash
chsh -s $(which zsh)
```

#### 2. Apply configuration

The automatic installer backs up existing supported configurations to a timestamped directory such as `~/.config.bak_{timestamp}` before creating the symbolic links. If you are installing manually, back up your existing configuration first.

2.1. Remove existing config and create the symbolic links to the config files

```bash
rm -rf ~/.config/{Thunar,btop,fastfetch,git,gtk-3.0,gtk-4.0,hypr,kitty,lsd,niri,noctalia,nvim,zsh}
ln -s ~/dotfiles/{Thunar,btop,fastfetch,git,gtk-3.0,gtk-4.0,hypr,kitty,lsd,niri,noctalia,nvim,zsh} ~/.config

echo 'export ZDOTDIR="$HOME/.config/zsh"' | sudo tee -a /etc/zsh/zshenv
```

2.2. Configuration git with your name and email

```bash title="~/dotfiles/git/config.local"
[user]
  name = arch-btw
  email = example@arch.btw
```

2.3. Enable some services

```bash
# ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw default deny routed
sudo ufw logging on
sudo ufw logging low
sudo ufw --force enable
sudo systemctl enable --now ufw.service

# bluetooth
sudo systemctl enable --now bluetooth.service

# power-profiles-daemon
sudo systemctl enable --now power-profiles-daemon.service

# docker
yay -S --needed --noconfirm docker docker-buildx docker-compose
sudo systemctl enable --now docker.service
sudo usermod -aG docker $USER
```

#### 3. Install GPU drivers

To have better performance and support for your graphics card, you need to install the appropriate GPU drivers for your system. The installation process varies depending on the type of graphics card you have.

<Callout type='info'>

If you are using the `linux-cachyos` kernel, you can skip this step. CachyOS
provides tools such as `chwd` to automatically detect your hardware and
configure the appropriate GPU drivers.

</Callout>

1. For `Nvidia` users

   If you are using an `Nvidia` graphics card, install the required packages:

   ```bash
   sudo pacman -S nvidia-open-dkms nvidia-utils linux-headers
   ```

   Then, add the following modules to `/etc/mkinitcpio.conf`:

   ```bash title="/etc/mkinitcpio.conf"
   MODULES=(... i915 nvidia nvidia_modeset nvidia_uvm nvidia_drm)
   ```

   Regenerate the initramfs:

   ```bash
   sudo mkinitcpio -P
   ```

   Then, add the following kernel parameters to `/etc/default/grub`:

   ```bash title="/etc/default/grub"
   GRUB_CMDLINE_LINUX_DEFAULT="... nvidia-drm.modeset=1 nvidia-drm.fbdev=1"
   ```

   Finally, regenerate the GRUB configuration:

   ```bash
   sudo grub-mkconfig -o /boot/grub/grub.cfg
   ```

2. For `AMD` users

   If you are using an `AMD` graphics card, install the required packages:

   ```bash
   sudo pacman -S mesa vulkan-radeon libva-mesa-driver mesa-vdpau
   ```

#### 4. Add CachyOS Optimized Repositories (Optional)

CachyOS provides optimized repositories and packages for Arch Linux. If you want to use them, you can enable the CachyOS repositories with the official setup script:

```bash
curl https://mirror.cachyos.org/cachyos-repo.tar.xz -o cachyos-repo.tar.xz
tar xvf cachyos-repo.tar.xz
cd cachyos-repo
sudo ./cachyos-repo.sh
```

After enabling the repositories, you can install the CachyOS kernel:

```bash
sudo pacman -S linux-cachyos linux-cachyos-headers
```

Then regenerate the GRUB configuration:

```bash
sudo grub-mkconfig -o /boot/grub/grub.cfg
```

If you no longer need the default Arch kernel, you can remove it:

```bash
sudo pacman -Runs linux linux-headers
```

GPU drivers do not need to be installed manually after this. Use `chwd` to detect and configure the appropriate drivers automatically:

```bash
sudo chwd -a
```

#### 5. Splash screen on boot (optional)

To add a splash screen on boot, you can use `plymouth`. First, install the `plymouth` package.

```bash
sudo pacman -S plymouth
```

Then, add the following line to your `/etc/mkinitcpio.conf` file to include `plymouth` in the initramfs.

```bash title="/etc/mkinitcpio.conf"
HOOKS=(... plymouth)
```

Then, add `splash` to the `GRUB_CMDLINE_LINUX_DEFAULT` variable in your `/etc/default/grub` file to enable the splash screen on boot.

```bash title="/etc/default/grub"
GRUB_CMDLINE_LINUX_DEFAULT="... splash"
```

Finally, config and regenerate the initramfs file to apply the changes.

```bash title="/etc/plymouth/plymouthd.conf"
[Daemon]
ShowDelay=0
Theme=bgrt # or any theme you like
```

```bash
sudo mkinitcpio -P
```

#### 6. Install `sddm` for display manager (optional)

To install `sddm` (Simple Desktop Display Manager) for managing graphical logins, you can follow the steps below:

1. Install `sddm` package for KDE Plasma integration:

   ```bash
   sudo pacman -S sddm
   ```

2. Enable the `sddm` service to start at boot:

   ```bash
   sudo systemctl enable sddm
   ```

#### 7. Install `vite-plus` for Node.js version management (it's required for some Neovim plugins)

You can install `vite-plus` from the AUR using `yay`:

```bash
yay -S vite-plus
```

After installation, restart your terminal and use `vite-plus` to install the latest LTS version of Node.js:

```bash
vp env install node@lts
vp env default node@lts
```

Verify the installation:

```bash
node -v
npm -v
```

Vite+ provides the `vp` CLI, which can manage Node.js runtimes and package managers in addition to the Vite toolchain.

#### 7. Fix Screen Sharing

If you encounter issues while sharing your screen on OBS Studio, Discord, or web browsers under Wayland, you need to install the appropriate `xdg-desktop-portal` backend for your compositor.

1. For Hyprland

   Hyprland uses its dedicated portal backend for screen sharing and window capture.

   Install the required packages:

   ```bash
   sudo pacman -S xdg-desktop-portal-hyprland
   ```

2. For Niri

   Niri uses the GNOME portal backend for screen sharing.

   Install the required package:

   ```bash
   sudo pacman -S xdg-desktop-portal-gnome
   ```

3. Restart the Portal Services

   After installing the appropriate backend, restart `xdg-desktop-portal` and the corresponding backend service.

   For Hyprland:

   ```bash
   systemctl --user restart xdg-desktop-portal.service
   systemctl --user restart xdg-desktop-portal-hyprland.service
   ```

   For Niri:

   ```bash
   systemctl --user restart xdg-desktop-portal.service
   systemctl --user restart xdg-desktop-portal-gnome.service
   ```

   Alternatively, you can simply reboot your system to ensure all portal services are restarted correctly.

#### 8. Fix windows 11 time

If it show wrong time on Windows, you can run the following command to fix it

```bash
timedatectl set-local-rtc 1
```

Or edit Registry Editor in Windows and change the value of `RealTimeIsUniversal` to `1` (DWORD) in the following path `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\TimeZoneInformation`

## Conclusion

Congratulations! You now have a flexible Arch Linux Wayland setup built around Hyprland and Niri, with a shared dotfile stack and a reproducible installation workflow.

The YukiOS installer is designed to make rebuilding the setup easier: choose your compositor, browser, and optional services once, review the installation plan, and let the script handle the repetitive configuration work. Existing supported configurations are backed up before the dotfiles are linked, and timestamped logs are kept under `~/.local/state/yukios/` for troubleshooting.

Whether you prefer Hyprland's dynamic tiling or Niri's scroll-tiling workflow, the goal is the same: a clean, fast, keyboard-driven Wayland desktop that can be reproduced from the dotfiles repository.

If you customize the setup, keep the dotfiles repository as the source of truth so the system remains easy to rebuild or migrate later. Happy ricing!
